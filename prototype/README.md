# AI 눈치게임 프로토타입 (Aeye)

AI 3명과 스페이스바로 눈치게임을 하고, 결과가 실시간 랭킹 현황판에 올라가는 프로토타입입니다.
AI는 판마다 참여자의 플레이 유형을 추정하고, 그에 맞춰 작전을 짭니다. 동작 원리는 [AI 시스템 설계](../docs/ai-system.md)에 있습니다.

| 화면 | 주소 |
|---|---|
| 게임 (1번 자리) | https://aiverse-nunchi.vercel.app/?station=1 |
| 게임 (2번 자리) | https://aiverse-nunchi.vercel.app/?station=2 |
| 데이터 수집 모드 | https://aiverse-nunchi.vercel.app/?mode=collect |
| 현황판 (랭킹) | https://aiverse-nunchi.vercel.app/board |

휴대폰(QR 참여)은 https://aiverse-nunchi.vercel.app/?station=qr 로 들어오면 됩니다. 아래 "휴대폰" 절을 보세요.

짧게 테스트하려면 게임 주소 뒤에 `&rounds=3`을 붙이세요. 기본은 10판이고, 판 수를 바꾼 게임은 **연습 게임**으로 저장되어 랭킹에 올라가지 않습니다.

## 랭킹 규칙과 보호

랭킹은 **누구나** 올라갈 수 있습니다. 부스 노트북이든, 사람이 많을 때 QR로 들어온 휴대폰이든 10판 일반 게임이면 같은 랭킹에 들어갑니다.
그 대신 아래로 기록을 지킵니다 (DB가 확인).

- **10판 게임만 랭킹**: `&rounds=3`처럼 판 수를 바꾼 게임은 연습 게임(`mode = 'test'`)으로 저장되고 랭킹에서 빠집니다.
- **너무 빨리 끝난 게임은 자동 숨김**: 10판은 카운트다운과 결과 화면만 합쳐도 1분이 넘게 걸립니다. 45초 안에 끝난 게임은 DB 함수를 직접 연달아 부른 것으로 보고 숨깁니다.
- **운영자 숨기기**: 이상한 기록은 아래 "기록 숨기기"로 바로 내립니다.
- **예전 점수 방식 함수(v1) 막음**: 한 판에 500점까지 넣을 수 있던 예전 함수는 부를 수 없습니다.
- 한계: AI 계산과 판정이 브라우저에서 이루어지므로, 시간을 맞춰 기록을 꾸며 보내는 것까지는 막지 못합니다. 행사 중 현황판을 보며 이상한 점수(한 판 최대 200점, 게임 최대 2,000점)는 숨깁니다.
- 휴대폰은 화면 아래 큰 빨간 버튼을 터치해서 참여합니다 (아래 "휴대폰").

## 구조

```
게임 화면 ──기록 저장(DB 함수)──▶ Supabase ──Realtime──▶ 현황판
  ├ ai/model.js   플레이어 모델 (유형 확률 + 개인 숫자)
  └ ai/planner.js 작전 계산 (공정 규칙 + 포획 확률 + 떠보기/공략)
sim/run.js  같은 ai/ 코드로 가상 플레이어와 수천 판을 돌려 밸런스 확인
```

- **Vercel**: `public/` 폴더의 화면 파일만 올립니다. 서버 코드는 없고, AI 계산도 모두 브라우저에서 합니다.
- **Supabase** (프로젝트 `aiverse-nunchi`, 서울 리전, 무료 플랜)
  - `nunchi_games` 게임 1판(10라운드)당 한 줄 (`mode`: play 랭킹 / test 연습 / collect 수집, 수집 모드의 연기 유형 `label`, 랭킹에서 숨김 `hidden`)
  - `nunchi_rounds` 라운드마다 한 줄 (4명 전원이 누른 시각, 연타 횟수, AI의 판단·작전·예상을 담은 `ai`)
  - `nunchi_ranking` 랭킹 (10판 일반 게임만, 숨긴 기록 제외, 동점이면 같은 순위)
  - 브라우저는 **읽기만** 가능하고, 저장은 `nunchi_start_game_v2` / `nunchi_record_round_v2` / `nunchi_finish_game` 함수로만 됩니다.
    점수와 총점은 DB가 계산합니다.
  - 전체 구조: [`supabase/schema.sql`](supabase/schema.sql). 예전 점수 방식의 v1 함수는 막아 두었습니다.

## 진행 순서

1. **닉네임 입력** (최대 12자, 비워두고 Enter를 누르면 회색 추천 닉네임 사용)
2. **스페이스바** (또는 엔터, 장면 속 빨간 버튼 클릭)로 버튼 누르기 × 10판
   - 카운트다운 동안 AI가 이번 판 작전을 확정합니다 (🔒, 참여자 입력은 보지 않음)
   - 1~3판은 AI가 떠보고, 4판부터 공략합니다
   - 게임 중에는 장면만 보입니다. 판이 끝나면 전광판에 생존·탈락과 점수만 짧게 뜨고, AI의 작전·예상·유형 확률 같은 세부 수치는 띄우지 않습니다
   - 중간에 전략을 바꾸면 AI가 알아채고 전광판에 "🔄 전략을 바꿨네?"를 띄운 뒤 새로 읽은 판단으로 공략합니다
3. 종료 화면 (결과)
   - 위: 총합 결과 — 점수, 생존 판 수, 순위, AI가 추정한 플레이 스타일, AI에게 읽힌 정도, 전략 변경 감지
   - 아래: 1~10판 목록 (판 · 떠보기/공략 · 누른 시각 · 결과). 판마다 **자세히보기**를 누르면 그 판의 타임라인, AI 포획 예상과 보너스, AI가 예상한 타이밍과 적중 여부, AI의 작전(미끼·매복·마지막 지키기), 그 판까지 본 "AI의 판단" 유형 확률이 펼쳐집니다 (한 번에 한 판)
   - 마지막 판 하나로 AI 판단의 1위 유형이 바뀌고 확신도 낮아지면, 플레이 스타일은 그 전 판까지의 판단으로 보여 주고 "🎭 마지막 판엔 평소와 다르게 눌렀어요"를 붙입니다 (화면 표시만. AI 계산·점수·기록은 그대로)
   - 맨 아래에 세 지표(유형 확률 · AI 포획 예상 · 읽힌 정도) 설명
   - 스페이스바나 엔터(또는 맨 아래 버튼)를 누르면 다음 사람. 마지막 판 직후 2초는 넘어가지 않습니다

## 규칙

- 시작 신호 후 5초 안에 한 번 누르기
- 0.15초 안에 2명 이상이 누르면 모두 탈락 (동시 입력, `CONFIG.collisionMs`). **참여자가 AI와 겹치면 그 순간 판이 끝나고 참여자 패배** (아직 안 누른 AI는 "판 종료")
- 가장 늦게 누르면 탈락. AI 3명이 모두 누르면 그 자리에서 판이 끝납니다 (아직 안 눌렀다면 마지막)
- 살아남으면 **100점 + AI 포획 예상 확률만큼 보너스** (예: AI가 78% 확률로 잡을 거라 봤는데 생존 → 178점). 탈락하면 0점
- AI는 0.1초~4.7초 사이에 누릅니다. 공정 규칙: AI끼리 0.18초 이상 간격, 가장 늦은 AI는 3초 이후, 살아남을 수 있는 시간 1초 이상

규칙 숫자는 `public/game.js`의 `CONFIG`와 `public/ai/planner.js`의 `DEFAULTS`에서 바꿀 수 있습니다.

## 화면 디자인 (픽셀 우주 정거장)

팀원이 준 시안 두 장(로봇 3종의 상태별 그림, LIVE 장면)을 따라 만든 화면입니다. 게임 화면과 현황판이 같은 색과 글꼴을 씁니다.

- 장면: 위쪽 벽의 전광판(라운드 · 큰 글씨 · 점수) → 청록 시간 막대 → 창밖 우주 앞 **둥근 빨간 탁자**. AI 3명 **ALPHA · BETA · GAMMA**는 탁자 뒤쪽 둘레에 앉고(양쪽은 조금 앞으로), 내 빨간 버튼은 탁자 한가운데(화면 정중앙), 이름표는 탁자 앞 가장자리에 놓입니다
- 로봇 그림은 상태마다 바뀝니다: 대기(`idle`) → 누름(`press`, 누른 순서가 별 말풍선으로) → 판 결과(`result`, 탈락한 로봇은 빨갛게 흔들림)
- 그림 파일: `public/img/bots/{alpha|beta|gamma}-{idle|press|result}.webp` (300×300, 배경 투명), `public/img/red-button.webp`. 같은 이름으로 바꿔 넣으면 그대로 반영됩니다
- 글꼴: [Galmuri11](https://github.com/quiple/galmuri) (SIL OFL), jsDelivr에서 받습니다. 못 받으면 기본 글꼴로 보여요
- 색과 모서리 깎기는 `shared.css`, 장면은 `game.css`, 현황판은 `board.css`
- 게임 중에는 장면이 화면 높이를 채웁니다 (남는 높이는 창밖 우주). 로봇과 버튼 크기는 화면 높이에 맞춰 바뀝니다. **부스 PC는 F11 전체 화면**을 권장해요. 1920×1080과 1366×768에서 스크롤 없이 한 화면에 들어옵니다(에뮬레이션으로 확인)
- 종료 화면은 판을 펼치면 길어지므로 화면 안에서 굴러갑니다

## 휴대폰

손가락으로 누르는 기기(휴대폰·태블릿)는 저절로 휴대폰 화면이 됩니다. PC는 그대로예요.

- 화면 아래에 엄지로 누르는 큰 빨간 버튼이 생깁니다 (장면 속 버튼 대신).
  - 카운트다운 동안: "준비…"
  - 판이 시작되면: "누르기!"
  - 누른 뒤: "눌렀어요"
  - 판 결과를 보는 동안에는 아래로 내려가요.
- 손가락이 화면에 닿는 순간을 누른 시각으로 기록합니다. 두 번 누르면 연타로 셉니다.
- 판마다 누른 방법을 `ai.input`(`key` 키보드 · `touch` 터치 · `mouse` 마우스)으로 남겨요. 휴대폰은 화면 반응이 늦어 시각이 조금 늦게 찍힐 수 있어서, 숫자 맞추기 도구에서 따로 비교해요.
- 종료 화면은 손가락으로 굴려 보면서 '자세히보기'를 누를 수 있고, 맨 아래 '처음 화면으로' 버튼을 누르면 돌아가요. (예전처럼 아무 데나 누르면 넘어가지 않아요)
- 좁은 화면에서는 위쪽 표시줄, 전광판, 로봇, 종료 화면을 작게 줄입니다. 전광판 높이는 고정이라 글이 길어져도 로봇이 들썩이지 않아요. 연결 상태는 초록 점만 보이고, 끊기면 글자로 알려 줘요.
- 게임 중 장면은 360×640에서도 한 화면에 들어옵니다. 아주 좁은 화면(380px 이하)의 판 목록은 '잡힘'처럼 짧게 쓰고, 탈락 이유는 자세히보기에 나와요.
- 랭킹은 휴대폰도 같은 규칙(10판 일반 게임)으로 올라갑니다.
- QR 주소는 `?station=qr`로 두면 기록에서 휴대폰 참여를 구분할 수 있어요.

## 데이터 수집 모드

주소에 `?mode=collect`를 붙이면 수집 모드입니다. 팀원이 유형을 정해 연기하며 플레이하고, 그 기록으로 AI의 숫자를 맞춥니다.

- 시작 화면에서 **연기할 유형**(즉시형 · 공격형 · 눈치형 · 버티기형 · 랜덤형 · 자유)을 고릅니다. 한 게임 동안 그 유형 하나만 진지하게 연기합니다.
- AI는 공정 규칙 안에서 **무작위로** 누릅니다 (AI의 예상은 기록만 해 둠). 그래서 점수는 의미가 없습니다.
- 기록에 유형 라벨과 연타 횟수가 붙고, **랭킹에는 올라가지 않습니다.**
- **한 판에 한 번만** 누릅니다. 카운트다운 중에 미리 누르거나 두 번 이상 누르면 화면에 경고가 뜨고, 그 판은 학습에서 빠집니다.
  종료 화면에 "학습에 쓰이는 판 n/10"이 나옵니다.
- **닉네임은 한 사람당 가명 하나**로 계속 씁니다 (예: `aeye1`). 같은 사람인지 알아야 사람마다의 차이를 계산하고 "한 사람을 빼고 검증"할 수 있습니다. 닉네임은 누구나 조회할 수 있으니 실명은 쓰지 않습니다.
  수집 모드에서는 닉네임을 비우면 시작되지 않고, 그 기기에서 마지막으로 쓴 가명이 자동으로 채워져요.
- **휴대폰으로도 수집할 수 있어요.** 휴대폰에서 같은 주소(`?mode=collect`)를 열고 화면 아래 버튼으로 누릅니다. 키보드 기록과 터치 기록은 숫자 맞추기 도구에서 나눠 볼 수 있어요.
- 권장: 1명이 즉시·공격·눈치·버티기 2게임씩 + 랜덤 1게임 (9게임, 약 20분). 유형 순서는 섞습니다.
- **더 모아도 됩니다.**
  - 한 유형만 몰아서 하지 말고, 유형마다 한 게임씩 '한 세트'로 더해 주세요.
  - 한 사람이 많이 하는 것보다 사람 수를 늘리는 게 효과가 큽니다. 숫자 맞추기 도구는 사람마다 같은 무게로 계산할 예정이라, 한 사람이 많이 해도 평균이 그 사람 쪽으로 쏠리지 않습니다.
  - 피곤하면 반응이 느려지고 연타가 늘어나므로 9게임마다 쉬어 주세요.

수집한 기록 보기 (Supabase SQL Editor):

```sql
select g.label, r.round, r.time_ms, r.presses, r.extra_presses, r.ai
from public.nunchi_rounds r join public.nunchi_games g on g.id = r.game_id
where g.mode = 'collect' order by g.started_at, r.round;
```

## 숫자 맞추기 도구

수집 모드 기록으로 AI의 유형별 숫자를 다시 맞춥니다. 습관(평균 시각·반응 시간), 사람 차이, 흔들림, 실수 비율을 맞춰요.

```bash
node prototype/sim/fit.js
```

```bash
node prototype/sim/fit.js --apply
```

```bash
node prototype/sim/fit.js --selftest
```

- `fit.js`: Supabase에서 수집 기록을 읽어 숫자를 맞추고 보고서만 출력합니다. 게임은 그대로예요. 후보 숫자는 `sim/results/params-candidate.json`에 저장돼요.
- `--apply`: 맞춘 숫자를 `public/ai/params.js`에 씁니다. 커밋·배포하면 게임에 반영돼요. 되돌리려면 그 파일의 값을 `null`로 두거나 git에서 이전 버전으로 돌립니다.
- `--selftest`: 정답을 아는 가상 데이터로, 도구가 숫자를 제대로 되찾는지 점검합니다.
- `--people 파일`: 수집 게임 정리 파일이에요. 기본은 `sim/people.json`이에요.
  - `people`: 닉네임이 섞인 게임을 한 사람으로 묶어요. 추천 닉네임은 다른 사람과 겹칠 수 있으니 게임 id로 지정해요.
  - `제외`: 게임 id와 이유를 적으면 그 게임은 숫자 맞추기에서 빼고, 검증에는 넣어요. 고른 유형과 전혀 다르게 연기한 게임 등에 써요.
- `--save 파일` / `--file 파일`: 기록을 저장해 두고 같은 기록으로 다시 돌려요. 기록 파일은 `prototype/sim/data/`에 두고 커밋하지 않습니다.
- `--input key|touch|all`: 키보드(부스) 기록이나 터치(휴대폰) 기록만으로 맞춰요. 기본은 all이에요. 둘이 섞여 있으면 보고서에 두 기록의 습관을 비교해 보여 줘요.
- `--only 유형,…`: 고른 숫자만 바꾸고 나머지는 model.js 기본값으로 둬요 (예: `--only fixed,follow`). 쓸 수 있는 값은 `instant` `fixed` `follow` `hold` `lapse`(실수 비율)예요. 검증도 고른 숫자만 바꾼 상태로 해요.

맞추는 방식

- 연타한 판은 뺍니다. 시각이 안 남은 판(AI 셋이 먼저 다 누름)은 "그때까지는 안 눌렀다"는 정보로 계산해요. 습관보다 한참 늦게까지 안 누른 판은 실수로 셉니다.
- 사람마다 같은 무게로 평균을 내고, 사람이 적으면 기본값 쪽으로 당겨요. 기본값을 습관은 사람 1명분, 사람 차이는 2명분, 흔들림은 10판분, 실수 비율은 40판분으로 칩니다.
- 공격형의 시각은 연기할 때 정한 값이라 흔들림만 맞추고, 랜덤형은 누른 시각 분포만 보고해요.
- 검증으로 실제 게임을 판마다 다시 돌려, 지금 숫자와 새 숫자를 비교합니다.
  - 미리 예상한 정도, 읽힌 정도, 유형 정답률, 잘못 감지, AI 포획 예상과 실제로 잡힌 비율(점수 공정성)을 봐요.
  - 사람이 2명 이상이면 한 사람씩 빼고 맞춘 뒤 그 사람으로 확인해요.
- 모든 유형에 3명 이상 모이고 검증 결과가 나아졌을 때 적용을 권장합니다. 적용 전에는 맞춘 숫자로 밸런스를 확인해요.

  ```bash
  SIM_PARAMS=prototype/sim/results/params-candidate.json SIM_PLAYERS=params node prototype/sim/run.js 150 1
  ```

## 시뮬레이터

```bash
node prototype/sim/run.js 150 1
```

유형별 가상 플레이어와 150게임씩 돌려 생존율, 점수, 유형 정답률, 계산 시간을 출력하고 `sim/results/latest.json`에 남깁니다.

- 바꾸지 않는 플레이어: 즉시형, 공격형, 눈치형, 버티기형, 랜덤형, 연타, 실수가 잦은 눈치형
- 중간에 전략을 바꾸는 플레이어: 4가지. 바꾼 뒤 몇 판 만에 다시 맞히는지, 전략 변경 감지율을 따로 출력

환경변수로 숫자를 바꿔 비교할 수 있습니다.
- `SIM_MODEL='{"switchWindow":0}'`: 모델 숫자 (이 예는 전략 변경 감지 끄기)
- `SIM_PLANNER='{...}'`: 작전 계산기 숫자
- `SIM_TAG=이름`: 결과를 `results/이름.json`으로 저장
- `SIM_PARAMS=파일`: 숫자 맞추기 도구가 만든 후보 숫자로
- `SIM_PLAYERS=params`: 가상 플레이어도 모델 숫자에서 뽑기. 맞춘 숫자를 쓰면 실제 사람에 가까운 가상 플레이어가 돼요

가상 플레이어 결과이며, 사람의 재미나 실제 정확도는 아닙니다.

## 현황판

- 닉네임과 점수 순위만 크게 보여줍니다. 어느 자리에서든 게임이 끝나면 그 줄이 반짝이며 바로 추가됩니다.
- 닉네임을 누르면 10판 기록 팝업이 열립니다 (판마다 누른 시각, 생존/탈락 이유, 점수, AI 포획 예상, AI 3명이 누른 위치, AI가 예상한 타이밍).
- 팝업은 ✕, Esc, 바깥 클릭으로 닫히고, 20초 동안 조작이 없으면 자동으로 닫힙니다.

## 배포 (자동)

GitHub 저장소의 `main` 브랜치에 push하면 Vercel이 **자동으로 배포**합니다. 따로 명령을 실행할 필요가 없습니다.

- Vercel 프로젝트 `aiverse-nunchi`가 이 저장소와 연결되어 있고, 루트 폴더는 `prototype`입니다.
- 배포 결과는 GitHub 커밋 옆의 체크 표시나 Vercel 대시보드에서 확인할 수 있습니다.
- `main`이 아닌 브랜치에 push하면 미리보기(Preview) 주소가 따로 만들어집니다. 미리보기 주소는 Vercel에 로그인한 팀 계정만 볼 수 있습니다.
- `.vercelignore`로 `public/` 화면 파일만 올라가고 `server.js`, `sim/` 등은 올라가지 않습니다.
- DB 함수를 바꿀 때는 지금 배포된 화면이 계속 동작하는지 먼저 확인합니다 (DB는 바로 바뀌고 화면은 push해야 바뀜).

## 기록 지우기

Supabase 대시보드 → SQL Editor에서 실행합니다. 라운드 기록은 게임과 함께 지워집니다.

```sql
-- 특정 닉네임만
delete from public.nunchi_games where nickname = '지울 닉네임';
-- 랭킹·연습 게임 전부 초기화 (수집 데이터는 남김) — 행사 전에 랭킹 비우기
delete from public.nunchi_games where mode in ('play', 'test');
```

### 기록 숨기기 (행사 중 이상한 기록)

지우지 않고 랭킹에서만 내립니다. 현황판에서 바로 사라집니다.

```sql
update public.nunchi_games set hidden = true where nickname = '숨길 닉네임' and mode = 'play';
-- 되돌리기: set hidden = false
```
