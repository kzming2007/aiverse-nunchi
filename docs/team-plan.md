# 준비 순서와 협업 방법

2026-11-14 제안을 11/16 메인 저장소로 옮기며 현재 상태를 반영했습니다. 담당과 기한은 팀의 가용시간을 보고 정합니다.

## 처음부터 포함하는 전체 범위

게임용 화면과 입력 장치 두 자리, 별도 현황판, QR 모바일 웹 참여, 개인 결과와 설명, 다음 참가자로의 전환을 함께 준비합니다. 단계별로 만든다는 이유로 이 범위를 삭제하지 않습니다. 줄이거나 바꾸는 경우에는 팀이 이유와 대안을 확인합니다.

| 순서 | 확인할 결과 | 제안 시점 | 상태 |
|---|---|---|---|
| 출발점 맞추기 | 기존 코드 유무, 가용시간과 담당, 첫 버전에서 비교할 규칙과 콘셉트 | 11/14~15 | 저장소 통합 완료(11/16), 담당 미정 |
| 한 회차 데모 | 안내 → 타이밍 게임 → 결과 → 다음 참가자. 키보드나 화면 입력으로 먼저 실행 | 11/16~18 | 프로토타입 완료(11/15, AI는 무작위) |
| 게임성 검토 | 직접 플레이하며 규칙 이해, 난이도, 적응 체감, 결과 만족감 확인. 필요하면 유형과 스테이지 비교 | 11/19~20 | |
| 운영 기능 연결 | 두 자리와 현황판, 모바일 접속, 실제 화면과 입력 및 음향 연결 | 11/21~23 | 두 자리·현황판 연결은 프로토타입에 있음 |
| 운영 연습 | 안내, 플레이, 결과 설명, 교대 흐름. 실제 소요시간과 장애 대응 확인 | 11/24~25 | |
| 설치 | 팀이 모일 시간과 현장 연결 확인 | 11/26 | |
| 행사 | 부스 운영 | 11/27 | |

위 개발 날짜는 Codex의 제안이며 팀의 약속이 아닙니다. 연결 기기, 입력 장치, 음향, 안내물 준비는 게임 제작과 병행합니다. 실제 버튼이 없어도 먼저 실행할 수 있게 하고 실물 연결은 확보 후 확인합니다.

## 분담할 작업

| 작업 묶음 | 범위 | 주담당 | 함께 확인 |
|---|---|---|---|
| 게임 흐름과 표현 | 입력과 판정, 화면과 상대 연출, 결과와 재시작 | | |
| AI와 비교 | 기본 상대, 개인 적응, 유형 가설, 협력과 비교 실험 | | |
| 연동과 운영 화면 | 회차 기록, 두 자리 집계, 현황판, QR 모바일과 연결 실패 처리 | | |

안내물, 효과음, 실제 장비 연결, 현장 진행도 담당을 맞춥니다. 위 세 묶음을 꼭 한 사람씩 고정해 맡을 필요는 없습니다. 어떤 부분을 주로 맡고 누가 함께 확인하는지 정하면 됩니다.

## 공통 기록 형식

처음 맞출 공통 정보는 회차와 판 식별, 규칙 버전, 사람 입력과 AI 예측/행동 시각, 판정, 점수와 취소 여부입니다. 유형이나 설명은 기능에 맞춰 더합니다. 기록 형식과 판정 변경은 서로 연결한 뒤 합칩니다.

현재 프로토타입은 Supabase에 다음을 저장합니다. ([`prototype/supabase/schema.sql`](../prototype/supabase/schema.sql))

| 공통 정보 | 지금 저장되는가 |
|---|---|
| 회차·판 식별 | 있음 (`nunchi_games.id`, `nunchi_rounds.round`) |
| 사람 입력 시각, AI 행동 시각 | 있음 (`time_ms`, 판마다 4명 전원의 `presses`) |
| 판정과 점수 | 있음 (`survived`, `reason`, `score` — 점수는 DB가 계산) |
| 규칙 버전 | 없음 |
| AI 예측 시각(사람이 언제 누를 거라고 봤는지) | 없음 — 예측 AI를 넣을 때 추가 |
| 취소 여부 | 없음 (끝까지 하지 않은 회차는 랭킹에 안 나옴) |
| 유형 라벨(데이터 수집용) | 없음 — 수집 모드를 만들 때 추가 |

## GitHub에서 이어가기

이 저장소(`aiverse-nunchi`)가 팀의 메인 저장소입니다.

1. Issue에 할 일, 관련 제안 ID, 담당과 완료 기준을 짧게 적습니다.
2. 기능별 브랜치에서 작업하고 다른 사람과 같은 파일을 바꿀 때 먼저 확인합니다.
3. PR에 바꾼 동작과 시험한 방법을 적고 다른 한 명이 읽은 뒤 합치는 방식으로 시작합니다.
4. **`main`에 합치면 Vercel에 자동 배포**되어 https://aiverse-nunchi.vercel.app 이 바로 바뀝니다. 브랜치에 push하면 미리보기 주소가 따로 생기니, 확인한 뒤 `main`에 합칩니다.

규칙과 콘셉트의 새 결정은 [제안 기록](ideas-and-decisions.md)에 연결합니다. 코드를 생성한 에이전트와 아이디어를 제안한 사람을 혼동하지 않도록 변경 설명에 구분합니다. 별도 기여도 점수나 복잡한 관리 절차는 만들지 않습니다.

공개 저장소이므로 팀원 이름·학번·연락처와 예산·현장 준비물 같은 내부 운영 정보는 올리지 않습니다. 실행 방법은 [prototype/README.md](../prototype/README.md)에 있습니다.
